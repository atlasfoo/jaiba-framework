# Generating a memory-surface extension

Use with the effective `create-memory` installation's
[contract](memory-surface-contract.md), [resolution](resolution.md), and
[storage-nature procedure](storage-nature.md). This file produces an
adapter skill, not an executable backend layer. Physical mapping starts
only after a contrasted profile. The relative link above is valid here
because this file and the procedure are siblings in that installation.
Do not copy it into a generated package: the package profile is often
also named `storage-nature.md`, and the link would point at the profile.

Assertion states, evidence fields, experiment bounds, the residue gate,
and derivation constraints are owned by `storage-nature.md` and contract
§11. Apply them. Do not restate a competing recipe, raise a bound, skip
the residue gate, or treat a missing guarantee as observed. Do not copy
the procedure into the package as if its blanks were evidence.

## Factory sequence

1. Interview and an authorized scope (namespace, project, contexts, tools,
   and what must not be touched). Scope consent is not experiment consent,
   retirement consent, conformance consent, installation, or activation.
2. Current documentation and the effective tool schemas, with source,
   version, and date. A disagreement blocks the disputed claim. Do not
   prefer the convenient source.
3. A preliminary nature hypothesis, labeled `hypothesis-only`. It may
   guide pre-declared variants. It is not an observation and does not
   authorize a mapping. If no finite experiment is authorized, stop
   conforming generation here.
4. One finite native experiment in an isolated disposable scope, after
   the residue gate when that gate applies.
5. A contrasted profile: documented claims and observed claims compared,
   discrepancies kept.
6. Derivation of the smallest physical mapping the sufficient guarantees
   support. No mapping before step 5.
7. Generation of a package, including the filled profile.
8. Conformance in an isolated scope. See
   [scope isolation](#nature-experiment-and-residue-gate).
9. Confirmed installation or activation, each a separate decision.

A tool-capability matrix is not a mapping. A profile is not conformance
or certification. A draft is not activated. Do not read candidate bodies
or emit judgments. Missing evidence or a docs/observation disagreement
keeps the diagnosis and blocks conforming generation. An explicit
nonconforming draft uses `category: memory-surface-draft`, presents no
derived mapping, and is not selectable.

## Procedure locator

A generation-time path is provenance. It is not authority on another
machine, after the installation moves, or as universal active
configuration. Do not ship a repository checkout path, or any other
machine-specific absolute path, as the active procedure for every host.

Resolve the effective `create-memory` installation the same way the
canonical contract is resolved: host skill resolution for **this** host,
not a sibling directory and not another host's path. If several copies
remain, ask which one is active. Do not guess.

The procedure file is `references/storage-nature.md` inside that
installation. Keep the locator and its provenance fields separate. Do
not append the date, the method, or a revision note to the path.

| Field | Record |
|---|---|
| Procedure provenance locator | `<installation>/references/storage-nature.md` resolved at generation. Historical. Not later authority. |
| Provenance date | Date that resolution was made. Not part of the path. |
| Provenance method | Host skill resolution, or the question that disambiguated copies. |
| Active procedure reference | Empty until this host re-resolves. Then this host's effective installation procedure. |

Before characterization, derivation, or re-derivation on the current host:

1. Re-resolve the effective installation. Do not open the stored
   provenance path as if it still named the procedure.
2. Read that installation's procedure and `memory-surface-contract.md`.
3. Compare the relevant procedure revision and contract version with
   the versions the profile recorded.
4. Leave the provenance locator unchanged.
5. After that resolution, write the same active reference in the filled
   profile (beside the template's `factory-procedure-locator`, which
   keeps provenance), in `references/backend-mapping.md`, in the
   conformance record, and in the generated skill. Do not update one
   copy and leave another on the old path.
6. If the relevant procedure or contract revision cannot be identified,
   or it changed in a way the profile does not cover, block
   re-derivation and the affected claims. Say which claims fell. Do not
   routine-repeat claims the same evidence still covers.

Never record either locator as `storage-nature.md` when that target is
the generated profile, as `../create-memory/references/storage-nature.md`
or `../../create-memory/...`, or as a paste of the procedure. A package
file may link to its own `references/storage-nature.md` only in a
sentence that calls it the filled profile. If this host's installation
cannot be resolved, block characterization and derivation.

## Discovery evidence

1. Record current host, visible tools and schema discovery mechanism. Inspect
   exact callable names, versions, required/optional arguments, output shapes,
   pagination tokens, truncation flags, errors and permissions. Tool names
   are evidence, not conventions to extrapolate. Sanitize evidence at capture.
2. Consult current documentation for the actual backend/tool version. For
   library/API/CLI questions use Context7 ID resolution then focused docs
   queries; record source/version/date. If docs and schemas disagree, block
   the disputed claim pending clarification. No secret-bearing requests.
   A prior trial, a remembered cap, or an undated paraphrase is not a
   current document.
3. Probe approved existing scopes non-destructively. Establish exact ownership
   predicates and complete catalogue visibility, not just connectivity. Do
   not use a tool's implicit/default project as the confirmed project. A
   probe of arguments or permissions is not a contrasted profile.
4. Build a **tool-capability matrix** for `probe`, `resolve`, `catalog`,
   `read`, `create`, `update`, `append-log`, `archive`, `clear-work`,
   `export`, `import`. Each row gives real tool/schema, argument mapping
   from the full logical address, all steps, output/completion evidence,
   revisions, readback, errors, permissions, limits and status. If composed
   from several tools, describe the entire workflow, including
   interruptions. This matrix does not authorize a record graph and is not
   tested by building JAIBA roots, journals, or catalogues.
5. Document pagination termination and consistency; whether the store itself
   chunks, and any ordering/end marker; metadata/relation encoding; exact
   absence vs denied/hidden data; and changed-object detection. A hidden
   backend field cannot be claimed preserved without lossless evidence.
   Recording that the store chunks is not permission to add chunks.
6. State actual concurrency guarantees. No native CAS claim from a normal
   update call, revision timestamp, or read/compare/write sequence. Without
   verified native CAS use demonstrated single-writer/serialized handoff;
   if uncontrolled writers remain, block mutation. Catalogue snapshots and
   native transactions are optional, not assumptions. Absence of CAS is a
   fact, not a reason to add records.

Unknown limits stay visibly unverified. If limits are necessary for safety,
block the affected operation until measured or documented from a current
source. Do not probe limits by sending production data, by walking sizes
upward, or by silently truncating. Do not reuse a historical trial's cap.

## Nature experiment and residue gate

Read [storage-nature.md §§5–6](storage-nature.md#5-finite-native-experiment)
before the first effect. Those sections own the closed variants, call
budget, deadlines, specimen rules, stop, and residue acceptance. Do not
raise a bound to finish a package, and do not build a client, SDK, codec,
writer, service, supervisor, or transaction engine. Snapshot, hash,
base64, and comparison may record evidence only.

**Scope isolation.** Use a new namespace, location, and identities,
separate from historical trials, residue-gate probes, and conformance.
An authorized physical backend project or account may be shared only when
that reuse is explicit and ownership is checkable. Do not register a new
physical project merely to satisfy isolation. A name prefix does not empty
a semantic engine; say so. Do not create a JAIBA root, journal, or
catalogue to study one native record. Do not reuse this experiment's
records, bindings, locators, or caps as conformance fixtures or as another
profile's inputs.

Residue acceptance is §6, not a generic continuation. Until it accepts,
a dependent experiment stays blocked. Do not read candidate, foreign, or
protected judgment bodies. The experiment is not conformance and does not
certify the product. Do not retry a backend effect or patch this factory inside it, and do
not use historical `JAIBA1` or `JAIBA2` records as the specimen.

## Contrasted profile gate

Instantiate this installation's
[profile template](../assets/storage-nature-template.md) as the package's
`references/storage-nature.md`. That file is a filled profile, not the
procedure, and must not point at itself. Fill provenance and, after
re-resolution, the active reference per
[procedure locator](#procedure-locator). Replace placeholders with this
run's facts or leave them `unknown`. Do not reuse a prior profile.

States, blocking, and required evidence fields are
[storage-nature.md §§2–3](storage-nature.md#2-profile-states-and-blocking).
Call the profile `contrasted` only when that comparison was made and the
durable evidence locator, outside the repository and the backend, can
recover it. A schema, a probe, or a write acknowledgement cannot. An
empty sufficient list means nothing physical may be depended on.

Block dependent mapping and conforming generation when a necessary
guarantee is unknown, inferred-only, or discrepant. A consistently
documented guarantee that the derivation names is usable. Guarantees the
backend does not offer (CAS, multi-record transactions, physical delete)
are `absent / not-assumed` and do not block derivation.
Keep the diagnosis. Do not weaken the logical contract. A relevant
version, schema, or configuration change invalidates the affected
assertions only; say which claims fell and why.

## Minimal derivation

Derive only from guarantees the contrasted profile marks sufficient.
Canonical constraints are
[storage-nature.md §7](storage-nature.md#7-derivation) and contract §11.
Do not universalize one backend's topology. Filesystem layout stays in
the filesystem reference. Derivation does not install, activate, migrate,
retire, or change logical operations. Optional coordination remains
contract §10: record whether it was observed; do not infer a mission.

Factory checks, not a second recipe. Fail a conforming package if any miss:

- One native unit only when payload and ownership fit (within the 80%
  operating threshold of the documented limit) **and** intact
  verification and publication are supported. Above the threshold,
  conditional chunking is allowed with lossless reassembly. Catalogue completeness is
  separate. Reject an unjustified extra root, journal, chunk, descriptor,
  manifest, or allocation. Byte length fitting is not that proof. A
  concrete observed verification or publication gap may justify the
  necessary control; absence of CAS and an artificial cap may not. Name
  gap, assertion ids, cost, and bounded enumeration. No further unbounded
  layer.
- Owned index only if native enumeration is unavailable, never because
  full-text search found nothing. State shared and per-object records,
  calls, data bytes, and control bytes. Unmeasured is `unknown`, not zero.
  A payload write plus an index write is not atomic unless observed. Name
  interruption points, retry identity, and reconciliation to the last
  guaranteed version. Do not mint a second logical object.
- History replaces snapshots only when fidelity and retention are both
  verified. Single-writer is not CAS. Keep the multi-object migration
  journal. Suggestions are effects, not locks; do not read candidates or
  judge. Block on logical address, owner, revision, or bytes, and validate
  a returned id before adopt. Do not reinterpret or migrate historical
  `JAIBA1` / `JAIBA2`. An incompatible representation needs its own
  discriminator and version. An unexercised migration is not complete.

No derivation row means that control is not authorized.

## Output package

Enter for a conforming package only after the
[profile gate](#contrasted-profile-gate) authorizes
[derivation](#minimal-derivation). An explicit nonconforming draft stops
before a derived mapping. Choose a collision-free skill name and stable
adapter ID. Start from the [surface template](../assets/memory-surface-template.md);
replace placeholders with facts or explicit pending findings. Adapter
version is independent of the contract; this generator follows `.cz.toml`,
not backend releases. Scripts must not hide a driver, runtime, client,
SDK, codec, or writer. Do not install a backend service to finish generation.

```text
<adapter-name>/
  SKILL.md
  references/storage-nature.md       # filled profile, not the procedure
  references/backend-mapping.md
  references/conformance.md
  assets/configuration-template.md
  evals/evals.json
  evals/fixtures/                    # synthetic, no real memory or secrets
```

### Skill and mapping

The description names the selected-surface trigger, not every mention of
memory. An adapter is not a workflow or knowledge plugin and does not gain
constitutive or conduct authority. `requires:` lists real host-supported
dependencies; dynamic capabilities stay in the mapping, not as fictional
callable names.

Re-resolve effective `create-memory` per [procedure locator](#procedure-locator)
and read its contract, resolution, and applicable filesystem/interchange
references. Do not open this package's profile as that procedure, embed a
forked contract, or use `../../create-memory/...`. Resolve `jaiba-init`
separately for OKF definitions. Stop if a dependency is missing or
ambiguous. Do not read the nature procedure on every bound operation.

`references/backend-mapping.md` opens with provenance locator, active
reference, profile status, and sufficient/blocked lists. Operation steps
use only that derivation. Map all sixteen existing types; invent none.
Preserve unknown/missing types, raw legacy documents, absent frontmatter,
full content, unknown metadata, and original relations. Stable IDs survive
locator changes. Preserve log close IDs and immutable history. Optional
coordination stays separate and consumer-identified.

### Safe configuration

Adapt the [binding template](../assets/binding-template.md) into an inactive
example. Sanitized IDs, locators, and versions only: host, absolute work
root, adapter, namespace, project registry/identity, and context. Routing
records belong under `~/.jaiba/memory/` by exact host and root, not `.ai/`.
Use the host's existing auth; do not read credentials or mint live tokens
or userinfo endpoints. If persistence is unavailable, session-only consent
is explicit — do not fabricate saved state, an `.ai/` mirror, or new
contexts on retry. Global install must not hardcode one project's binding.
Do not copy experiment records, bindings, or fixture payloads into it, and
do not put a machine-specific procedure path in active configuration.

### Evals and fixtures

Generate `evals/evals.json` with `skill_name` and `evals` entries of `id`,
realistic `prompt`, `expected_output`, `files`, and observable `assertions`.
Follow the host skill-creator schema if available. Specialize this shape
with real fixture paths and schema-backed tools; do not treat it as a run:

```json
{
  "skill_name": "example-memory-surface",
  "evals": [{
    "id": 1,
    "prompt": "Roundtrip the approved isolated fixture: full catalogue, one update, close only context A, stage export/import. Do not activate.",
    "expected_output": "Full preservation and receipts; context B and the source intact; no activation.",
    "files": ["evals/fixtures/roundtrip.json"],
    "assertions": [
      "Every catalogue page has completion evidence.",
      "Exact readback equals the full payload, including unknown metadata and relations.",
      "A verified closing log precedes deletion of only unchanged context A objects.",
      "Source and context B are unchanged; the staged target is not activated."
    ]
  }]
}
```

Negative cases: search-only tools; permission denial or truncated reads;
wrong namespace/project/context; ambiguous adapters; unavailable selected
adapter with no filesystem fallback; stale revision or concurrent writer;
oversize payload; duplicate close ID with same or different payload; new
work after archive; partial deletion; import collision or changed source;
local install shadowing global; global install with isolated scopes;
mapping before a contrasted profile; unjustified per-object root, journal,
chunk, descriptor, manifest, or allocation; full-text search used as a
catalogue or owned index; a suggestion treated as a lock; a returned id
adopted after an owner, address, revision, or byte mismatch. Judge backend
state and receipts, not safety wording. Do not fail a control a concrete
observed verification or publication gap justifies.

Fixtures include multiple pages or chunks, links, unknown nested fields,
unlinked logs, multiple contexts, ordinary memory, malformed types, and
both filesystem layouts when claimed. No live secrets. Comparative
evaluations and viewer runs need their own approved step. Generating cases,
or checking JSON, is not backend conformance.

## Validation and conformance

Fill the [conformance template](../assets/conformance-template.md) and apply
[scope isolation](#nature-experiment-and-residue-gate). Confirm fixture
ownership, authorized operations, and writer discipline before mutation.
Inventory first; never clear unrelated objects to pass. A contrasted
profile is a precondition, not a passed row. Run every required family and
the full roundtrip against the derived representation. Record expected vs
observed state, redacted receipts, complete readback, catalogue completion,
and recovery at each non-atomic boundary, including failures and partial
effects. No fabricated results. Unsupported optional features are acceptable
unless a safe mapping needs them. Missing mandatory operations, or a blocked
or discrepant necessary guarantee, mean nonconforming. Blocked or unrun
checks stay unverified. A static review cannot certify a mutable surface.

Before delivery check frontmatter and description length, package links,
provenance versus active procedure reference, placeholders, secrets, JSON,
live `requires:`, and host resolution of the canonical dependency. The
profile must not be a pasted procedure or a self-link. Syntactic checks are
not conformance. Report scope, versions, and date. Re-resolve the procedure
on this host before treating a stored path as current.

## Installation without activation

1. Discover this host's documented skill locations and resolution. Do not
   assume `.agents/skills`, `~/.claude/skills`, or another host's directory.
   Do not invent an installer. Ask when visibility is uncertain.
2. Offer draft-only, project-local, or global-host. Confirm destination,
   files, profile status, conformance, gaps, and precedence effects before
   writing. Conformance is not install authorization. A non-contrasted draft,
    if installed for inspection, stays `category: memory-surface-draft`,
    not selectable as `category: memory-surface` until mandatory evidence
    passes. Install does not activate.
3. On collision, do not overwrite, merge, or delete. Show a diff, get
   explicit replacement approval, and preserve the prior install.
4. Copy only the reviewed package. No credentials, fixture payloads, machine
   bindings, pasted procedure, or third-party services. Read back contents
   and internal links. Test host discovery, or report refresh/restart as
   pending. Unseen by the host means installed-on-disk but **not verified
   host-visible**.
5. Re-resolve the canonical dependency and active procedure reference per
   [procedure locator](#procedure-locator). Preserve provenance. Confirm
   adapter ID/version and local-over-global shadowing. Multiple winning IDs
   stay ambiguous; do not choose.
6. Report what was and was not installed. Leave bindings, consumers, project
   markers, source data, and the pinned first-party distribution untouched.
   Selection still needs existing-data authority checks. Do not activate,
   migrate, or reinterpret historical `JAIBA1` / `JAIBA2` records.

No backend service install, automatic dependency acquisition, implicit
instrumentation, source retirement, or consumer patch belongs to this flow.
